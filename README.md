# AveSepHelper

Оконная программа на Rust для Windows: подготовка готовых модов Sephiria к публикации в Steam Workshop. Интерфейс на русском. Steam и игра для работы редактора не требуются.

## Запуск

Откройте `AveSepHelper.exe` из папки `dist`. Установка и права администратора не нужны. После загрузки исходников в репозиторий и успешной сборки готовый архив будет доступен в **Actions → Windows build → успешный запуск → Artifacts → AveSepHelper-Windows** (для скачивания артефактов нужен вход в GitHub). Репозиторий проекта: [AveSepHelper](https://github.com/imkita339-afk/AveSepHelper).

1. Выберите исходную папку с файлами мода. Если в ней есть `metadata.json`, программа загрузит его; иначе предложит заполнить новый.
2. Дождитесь автоматического поиска. Помощник проверяет все подпапки и показывает найденные компоненты, библиотеки и обложки. Если внутри несколько самостоятельных модов, выберите один. Если мод один и спрятан во вложенной папке, помощник откроет его автоматически. В **Посмотреть и выбрать найденные файлы** можно уточнить состав; выбор сохраняется сразу. Для нестандартных компонентов доступна ручная настройка.
3. Нажмите **Далее: оформление**. Заполните название, описание, автора и версию. Выберите категории и обложку. Рядом отображается пример карточки мода.
4. Новому моду автоматически назначается уникальный код (modId). Изменить его до первой публикации, а также настроить мультиплеер можно в разделе **Другие настройки мода**. Библиотеки, зависимости и переводы доступны в раскрывающемся редакторе JSON для опытных авторов.
5. Нажмите **Далее: проверка**. Выберите папку игры — программа подготовит мод в её WorkshopLocal и создаст WorkshopLocal, если она отсутствует. Можно выбрать отдельную папку для сборок. Ошибки и примечания показываются здесь же; проверка выполняется в фоне.
6. Исправьте ошибки, если они есть, и нажмите **Создать папку мода** либо **Обновить папку мода**. На этом этапе лучше закрыть игру. После подготовки откройте результат кнопкой внизу окна и следуйте инструкции на экране.

Выбранная отдельная обложка PNG/JPG будет преобразована в JPG не больше 1024 px и меньше 1 МБ. Исходная картинка не изменится. Если новую обложку не выбирать, программа использует путь из метаданных или стандартный файл thumbnail/preview в папке мода.

Результат: `<назначение>/<modId>/metadata.json` и файлы мода. Исходник остаётся нетронутым. Изменения формы сохраняются в результирующий пакет; отдельного сохранения проекта редактора нет. Чтобы продолжить редактирование, загрузите подготовленную папку как исходник с другим местом назначения.

## Обновление публикации

При повторной подготовке в существующую папку:

- `modId` должен совпадать; версия должна отличаться от предыдущей — увеличивайте её при обновлении;
- `uploadticket.json` из существующей сборки имеет приоритет над копией в исходнике;
- предыдущая папка целиком перемещается в `<назначение>/.sephiria-prep-backups/`;
- замена происходит только после подготовки и повторной проверки новой сборки;
- если размещение новой сборки не удалось, программа пытается вернуть предыдущую папку.

Если в исходнике есть `uploadticket.json`, изменение modId запрещено. Сохраняйте билет вместе с резервными копиями. Программа не объединяет прочие файлы предыдущей сборки с исходником: всё нужное содержимое должно быть в исходной папке.

## Проверки

### Автоматический поиск

- Переводы определяются по поддерживаемому коду языка в имени JSON и таблице `ключ → строка`, независимо от названия и глубины папки.
- Костюмы и скины определяются по `costume.json` / `skin.json`, полям `id`, `name`, `animations`; группируются в модуль папки костюмов.
- Управляемые DLL разбираются статически как PE/CLI: помощник читает типы и их наследование от `WorkshopModBase` / `HorayModBase`, **не запуская код DLL**. При одной найденной точке входа заполнит `entryClass`. При нескольких классах или разных сборках с одинаковой точкой входа предложит выбрать.
- Управляемые DLL без распознанной точки входа предлагаются как вспомогательные библиотеки, если найден DLL-мод. Проверьте их назначение; библиотеки с одинаковыми именами из разных сборок не выбираются автоматически.
- Во вложенных папках ищутся `thumbnail`, `preview`, `cover`, `banner` в PNG/JPG. Найденные обложки можно переключать на экране оформления. Картинки из обнаруженных папок костюмов не используются как обложки автоматически.
- Папки `Data` и `Packs` предлагаются на подтверждение: по названию нельзя надёжно определить назначение произвольных данных.
- Существующие метаданные и неизвестные поля сохраняются. Повторный поиск сохраняет правки формы. Выбранные DLL перечисляются в metadata; остальные DLL исключаются из готового пакета с примечанием. Исходные файлы не удаляются.

Ограничения: языковые JSON должны находиться в отдельной папке внутри мода, а костюмы — иметь структуру `ПапкаКостюмов/Имя/costume.json`. Вложенные классы DLL и наследование через базовый класс из другой сборки могут потребовать ручного entryClass. Проверка наличия публичного конструктора и работоспособности кода остаётся за игрой. DLL больше 64 МБ не анализируются автоматически; JSON анализа ограничены 16 МБ. Поиск ограничен 20 000 объектами и 32 уровнями вложенности; ссылки/junction и папки сборочных промежуточных файлов не обходятся.

### Оформление и пакет

- Структура JSON, schemaVersion, modId, версия, длина названия/описания и известные теги.
- Четыре типа модулей, наличие файлов/папок, entryClass, повторное объявление DLL и библиотек, consumer/dependencies.
- Относительные пути с точным регистром, запрет `..`, абсолютных путей, символических ссылок и junction внутри пакета.
- Читаемость PNG/JPG и ограничение размера; синтаксис JSON локализаций.
- В оконном помощнике невыбранные DLL, включая игровые копии, пропускаются с примечанием. Явно объявленные игровые/системные сборки (Assembly-CSharp, UnityEngine, UnityEditor, mscorlib, netstandard) блокируют подготовку. Программный API `validate/build` дополнительно сохраняет строгий режим, где любая необъявленная DLL считается ошибкой.
- Исключение из сборки `.git`, `.vs`, `.idea`, `obj`, `target`, `node_modules`, `__pycache__`, `.pdb`, `.csproj`, `.sln`, `.user`, `.tmp` и устаревших mod-guard manifests. Каталог `bin` сохраняется: там могут лежать нужные DLL.

Редактор полного JSON позволяет задать `libraries`, `dependencies`, дополнительные поля и языковые карты. Неизвестные поля сохраняются. Для многоязычного названия/описания форма редактирует `en-US`, сохраняя остальные переводы.

Программа проверяет подготовку пакета, а не корректность игровой логики, сигнатуры entryClass или безопасность DLL. Формат костюмов и семантика локализаций требуют проверки в игре. Не все игровые библиотеки можно определить по имени — дополнительно проверьте список файлов. Лимит проверки кода **20 МБ в сжатом виде** показывается как напоминание: серверный архив здесь не создаётся и его размер не измеряется.

## Публикация

Программа не загружает мод в Steam. Запустите Sephiria, проверьте локальный мод и используйте **Мастерская Steam → Мои моды → Загрузить в Мастерскую**. Это также отправит DLL на проверку. Затем проверьте копию по подписке и измените видимость на «Для всех». Для тестирования мультиплеера уберите локальную папку из `WorkshopLocal` и используйте подписку.

Официальные источники:

- [metadata.json](https://github.com/team-horay/sephiria_modding/blob/main/docs/ru/metadata.md)
- [Публикация](https://github.com/team-horay/sephiria_modding/blob/main/docs/ru/publishing.md)

## Визуальные эффекты

Мягкое появление экранов, подсветка кнопок при наведении, движущийся индикатор поиска и короткое появление галочки с частицами при успешной подготовке. Постоянных фоновых частиц нет. Переключатель **Мягкие анимации** внизу боковой панели отключает движение на время текущего запуска. Проверка и подготовка файлов выполняются в фоне.

## Сборка из исходников

Нужны Rust с Windows MSVC toolchain и Visual Studio C++ Build Tools:

```powershell
cargo build --release --locked
cargo test --locked
```

Либо запустите `Build.bat`, чтобы собрать и скопировать программу в `dist/AveSepHelper.exe`. Зависимости закреплены в `Cargo.lock`. Нативные диалоги выбора Windows реализованы через COM; PowerShell программе не нужен. GitHub Actions выполняет форматирование, Clippy, тесты и создаёт переносимую Windows-сборку. Исполняемые файлы, временные данные и резервные копии не включаются в историю Git.

Тест junction помечен ignored: ограниченная среда запрещает создавать точки соединения. В среде с нужными разрешениями: `cargo test --test preparation junction_is_rejected -- --ignored`.

Тест на официальной DLL-примерe запускается отдельно: задайте `AVE_TEST_DLL_SAMPLE` путём к `PhysicalDamagePlus.dll` из официального `examples/dll-sample/package/bin/`, затем выполните `cargo test --lib managed::tests::official_sample -- --ignored`. DLL не исполняется и в этот репозиторий не включена.
